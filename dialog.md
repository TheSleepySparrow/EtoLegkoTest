# Диалог по разработке скрипта бенчмаркинга

## Исходное задание

Необходимо выполнить небольшое задание. Представь, что ты крутой backend-разработчик, разбирающийся в Node.js. Тебе необходимо написать консольный скрипт. Этот скрипт должен:
- принимать адрес (url) через консольный ввод;
- отправлять 10 последовательных запросов по этому адресу, дожидаясь ответа на каждый запрос;
- после чего считает среднее время запроса, общий объем скачанных данных и средний объем скачанных данных;
- выводит в консоль скорость скачивания данных (общий объем / общее время запроса).

Помимо скрипта напиши README-файл в котором будет даваться краткое описание работы скрипта, инструкции по запуску, а также прописаны единицы измерения всех переменных (объем / время запроса / скорость).

Задай все уточныющие вопросы, которые могут у тебя возникнуть. Задавай их до тех пор пока не поймешь полностью реализацию задания.

Как итог я должна получить два файла (скрипт + readme), скрипт обязательно должен быть рабочим, чтобы я могла его запустить на своей локальной машине.

## Уточняющие вопросы

**Вопрос 1: Метод HTTP запроса** — какой метод использовать? GET, HEAD или другой?

**Вопрос 2: Способ передачи URL** — как именно пользователь должен передавать адрес:
- Через аргументы командной строки: `node script.js https://example.com`
- Через интерактивный ввод после запуска скрипта
- Или оба варианта?

**Вопрос 3: Обработка ошибок** — что делать, если какой-то запрос не удался (ошибка сети, таймаут, невалидный URL)?
- Прерывать выполнение
- Пропускать неудачный запрос и продолжать
- Повторять запрос

**Вопрос 4: Таймаут запроса** — нужно ли устанавливать максимальное время ожидания ответа? Если да, то сколько?

**Вопрос 5: Учет объема данных** — что считать "объемом скачанных данных":
- Размер тела ответа (body)
- Размер тела + заголовки
- Только заголовки (если используется HEAD)

**Вопрос 6: Формат вывода** — в каком формате выводить результаты? Например:

```markdown
Среднее время запроса: 150 мс
Общий объем данных: 5.2 МБ
Средний объем данных: 520 КБ
Скорость скачивания: 34.7 МБ/с
```
Или нужен другой формат?

**Вопрос 7: Использование библиотек** — использовать только встроенные модули Node.js или можно подключать внешние библиотеки (например, `axios`, `node-fetch`)?

**Вопрос 8: Версия Node.js** — на какой минимальной версии Node.js должен работать скрипт?

**Вопрос 9: Единицы измерения в выводе** — в каких единицах выводить:
- Время: миллисекунды или секунды?
- Объем: байты, килобайты, мегабайты?
- Скорость: КБ/с, МБ/с?

## Ответы на вопросы

**Ответ 1:** Используется метод GET

**Ответ 2:** Я предпочту оба варианта, однако сейчас делается упор на корректной базовой реализации, поэтому передачи url происходит из ввода после запуска (вариант 2)

Но проверка на валидный url должна быть в самом сразу после получения url (как первый запрос - если не валидно, то дальше расчеты не производятся и пользователю выводится соответствующая информация).

**Ответ 4:** Таймаут должен быть - 15 секунд

**Ответ 5:** В качестве объема данных выступает полезная информация запроса - его body

**Ответ 6:** Представленный тобой формат подходит

**Ответ 7:** Можешь использовать дополнительные библиотеки при условии что это улучшит код / сделает скрипт легче читаемым / снизит время работы скрипта и т.д.

**Ответ 8:** Версия 26 (также отрази это в readme)

**Ответ 9:** Время - миллисекунды, объем - килобайты, скорость - МБ/с

## Итоговая спецификация

На основе полученных ответов была определена следующая спецификация:

### Функциональные требования
- Метод запроса: HTTP GET
- Ввод URL: интерактивный ввод после запуска скрипта
- Количество запросов: 10 последовательных запросов
- Таймаут: 15 секунд на каждый запрос

### Обработка ошибок
- Проверка валидности URL перед началом работы
- Первый запрос как проверка доступности ресурса
- При неудачном запросе: пропуск, продолжение работы, исключение из расчетов
- При невалидном URL или недоступности ресурса: завершение работы с сообщением об ошибке

### Измерения
- Время: миллисекунды (мс)
- Объем данных: килобайты (КБ), учитывается только body
- Скорость: мегабайты в секунду (МБ/с)

### Технические требования
- Минимальная версия Node.js: 26
- Использование только встроенных модулей (для простоты и отсутствия зависимостей)
- Поддержка HTTP и HTTPS протоколов

### Вывод результатов
- Среднее время запроса (мс)
- Общий объем скачанных данных (КБ)
- Средний объем данных за запрос (КБ)
- Скорость скачивания (МБ/с)
- Количество успешных запросов
